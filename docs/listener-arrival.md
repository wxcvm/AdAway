# AdGuard DNS 指向与响应服务器到达检测

设置提供独立的“检测 DNS 与请求到达”按钮，按已应用的监听配置运行，编辑草稿不启动检测。广告规则与 Hosts 规则测试域名均可填写或留空。
预设 ad.doubleclick.net 来自 AdGuard 官方介绍中的 DNS 广告域名示例；不保证命中用户当前订阅、白名单或实际规则类别。
参考：https://kb.adguard.com/kb/pt-BR/general/ad-filtering/how-ad-blocking-works/

检测分别报告已安装、主进程运行、VPN 所有者证据、AdGuard OUTPUT NAT 规则、管理端口回执、每个 HTTP 响应入口回执、测试域名 A/AAAA 的系统解析结果与实际 HTTP 到达。
已安装不等于正在运行，有 VPN 不等于归属 AdGuard，有 NAT 规则不等于本次请求命中，TCP 成功不等于 AdAway 收到。没有足够证据时显示未知或未确认，不推断 AdGuard 一定拦走请求。
AdGuard 的两类拦截模式需要各自填写自定义 IP；DNS 返回值本身不能证明匹配的是哪种语法，类别与规则命中以 AdGuard 过滤日志为准。

用户主动检测时，向当前本机监听及回环管理端口发送随机 128 位 nonce。生产原生 HTTP 入口在任何转发前处理固定 /adaway-listener-probe/<32 hex>，只回显固定格式回执。
GET 之外拒绝，非法 nonce 拒绝，响应 no-store。端点不返回统计、配置、证书或浏览记录，不转发请求，不修改规则，不计入用户拦截排行。它是公开的无状态到达回执，不是身份认证协议。

系统 DNS 查询支持完整 ASCII/xn-- 域名，拒绝 URL、路径、IP、换行或含糊 Unicode 输入；不更改已有规则的 IDN 行为。
解析后台线程最多一个，2 秒等待，取消不产生无界线程。只有匹配已应用监听且属于本机的解析地址才连接；公网返回直接报告不匹配，不访问广告源站。
每个本机请求最多 2 秒、4096 字节，不跟随重定向、不使用系统 HTTP 代理。当前检测验证 HTTP 请求到达，不关闭 HTTPS 验证、不代表客户端证书信任或其他应用流量路径通过。
读取 Root 进程/NAT 只在已有授权时进行；没有授权显示未读取，不因打开设置申请 Root，不读取 AdGuard 私有配置，不修改其规则、DNS、证书或网络。

共享 native 回执处理器与 Java 客户端在 API 30/35 用真实 IPv4/IPv6 套接字对照；JVM 验证随机回执、错误 nonce、普通页面、重定向、DNS 不匹配不连接及输入校验；UI 验证两个域名可编辑但不自动检测。

## 进度、取消与重试

检测期间显示当前阶段，提供“取消检测”；离开页面也会取消本次会话。取消会关闭本次 HTTP／TLS 连接并停止后续地址探测，不会关闭服务器或其他会话的连接。界面等本次等待和清理返回后再允许重试，迟到回调不能覆盖新一轮结果。

新一轮运行、失败或取消均保留上次完成的报告；用户可选择报告文本或点击“复制结果”。进度与报告分开显示，取消不能被描述成检测成功。

系统 DNS 和已提交的只读 Root 观察未必能被系统立即中止；取消停止本应用的等待，后台操作可能稍后结束。DNS 保留单个未结束解析任务的限制；Root 观察也只允许一个未结束任务，最多等待两秒，超时或取消后重试不会重复排队。没有杀死共享 Root shell、清空 DNS 缓存或修改系统网络。

只读诊断不再为整个检测持有监听控制锁，避免长时间阻塞正常的启动／停止操作。配置仍在开始时取快照，后续界面草稿不改变本次目标。现有 HTTP 2 秒／4096 字节、DNS 2 秒和 TLS 看门狗限额保持不变。
