> 状态：**规格已定**（本文件），**UI 改造待做** —— 改造需要看到真实界面（控件位置、折叠状态、文案长度、
> 中英文案换行）才能定，盲改 Composable 的风险大于收益。本文件是把"7 组 + 统一模板"先钉下来，供改造时逐项核对。

## 2. 目标：7 组（每个现有分区都必须落到某一组，不新增语义）

| # | 组 | 归入的现有分区 |
|---|---|---|
| 1 | **拦截与重定向** | 拦截模式；自定义重定向地址；允许清单 |
| 2 | **Web 服务器与端口** | Web 服务器设置；轻量模式 |
| 3 | **证书与 HTTPS** | 证书管理区；一键信任 / 手动安装；固定证书的应用 |
| 4 | **内容与规则** | 可见型占位；F5 去重 / 重试护栏；决策缓存 / 按域熔断；按域覆盖响应 |
| 5 | **统计与图表** | 统计图表设置；实时推送；趋势范围；图表样式 |
| 6 | **应用、外观与后台** | 应用监控；开机自动启动；省内存；**外观/主题（Appearance (theme)）** |
| 7 | **数据与关于** | 数据管理；备份 / 恢复；调试；更多设置；关于 |

## 3. 统一模板：每一项都必须能回答五个问题

**名称 → 作用 → 当前状态 → 控件 → 生效方式**

- **名称**：用户能看懂的中文名（不是键名）；
- **作用**：一句话说清"打开/关闭后会发生什么"；
- **当前状态**：**真实状态**，不是配置值 —— 例如端口冲突时要显示"配置值 8080 / 生效中 8081（被占用）"，
  失败要显示原因，而不是静默改成别的值；
- **控件**：开关 / 下拉 / 输入框 / 按钮；
- **生效方式**：即时 / 重载后 / 重启后 / 需重新同步 —— **必须写明**，不许让用户猜。

示例（照此格式逐项补齐）：

| 名称 | 作用 | 当前状态 | 控件 | 生效方式 |
|---|---|---|---|---|
| 按域熔断 | 某域名连续快速失败达到阈值后，在冷却期内直接快速失败 | 关（默认关） | 开关 | 即时（写 `block_config.json` 后热加载） |
| 证书（用户库 / 系统级） | 用户库：多数 App 默认不信任；系统级需写入 `/system` 或 APEX/apexdata | 未安装 / 用户级 / 系统级 / 已变化（安装·删除·重启后重新计算） | 按钮 + 状态行 | 即时（重新探测） |
| 拦截模式 | 127.0.0.1 = 本机拦截页；0.0.0.0 = 空路由（可与 AdGuard 等共存） | 当前生效值 + 来源 | 单选 | 重载后 |

## 4. 改造时的验收清单（做完逐条核对）

1. 7 组顺序如上，**每个现有分区都能在某一组里找到**（没有设置被弄丢）；
   —— 已用代码核对过：`SettingsScreen.kt` 里的 **20 个分区注释逐一有归属**（20/20）；
   核对时发现**外观/主题（Appearance (theme)）**原先无归属，已并入第 6 组（组名相应改为「应用、外观与后台」，仍是 7 组）。
2. 每项都补齐五段模板，**"生效方式"无一遗漏**；
3. 状态行显示**真实状态**：端口冲突显示来源；证书显示四态之一；模式显示"配置值/生效中/成功/失败(原因)"；
4. 文案全部走 `strings_compose.xml` + `values-zh`（C7 已完成的部分不得回退）；
5. 无障碍：每个开关都有可读标签与"在统计中显示"这类补充说明（C8 已完成的部分不得回退）；
6. 改造后 **CI 绿** + `chart_style` 等既有键名不变（避免用户配置失效）。
> **补充事实**：并非每个分区都有 `*_title`（例如「应用监控」就没有，它的分区前缀下只有 `app_monitor`、`app_allow*`、`app_sub`）。因此取键规则是：**有 `*_title` 用 title，没有就用该分区最具体、最贴近的那把键**，并始终通过「存在性 + 键名含概念词」两道校验。

> **五段的取键规则**（后来改界面的人请照此引用）：
> 名称列引分区的 `*_title`（没有 title 才退回最贴近的分区级键）；作用列引该分区的 `*_hint`；
> 引用必须**真实存在**（机器交叉核对）且**键名含该分区概念词**。此规则是因为前两批草稿曾误引子项
> （如把「在统计中显示」引成统计行、把「关于」引成仓库链接）而收紧的。

## 5. 逐项模板草稿（**依据应用现有文案**，待截图后核对）

> 说明：本表只把应用**已有的文案**填进五段模板，**不臆造语义**；凡现有文案未覆盖的，明确写「改造时需补/需确认」。
> 依据：`app/src/main/res/values-zh/strings_compose.xml` 与 `values/strings_compose.xml`。

> **更正记录**：本表最初把「自定义重定向地址」与「允许清单」两项标为「现有文案中未找到对应 hint」✗，
> 那是本表的**匹配范围太窄**造成的**假缺口**：重定向的文案在 `compose_rules_*` 命名空间下；
> 允许清单相关键其实有 **32 个**、中英齐备。经逐个打印候选键核对后已改为上表的真实文案。
> 另附一个正面例证：`compose_exempt_effective_note` 主动讲清「解除过滤」的**真实效果**
> （回 204 No Content；在「AdGuard 把拦截 IP 指向本服务器」的部署里服务器拿不到真实内容）——
> 属于本项目「不谎报」要求的正确示范。

| 名称 | 作用（引自现有 hint 文案） | 当前状态 | 控件 | 生效方式 |
|---|---|---|---|---|
| 拦截模式 | 本机拦截：由内置 Web 服务器返回拦截页与占位图，可统计每个应用的拦截量（需占用 80/443 端口）。 | 见设置页状态行（需截图确认最终措辞） | 单选（本机拦截 / 空路由） | 重载后（写入 hosts 规则与配置） |
| 自定义重定向地址 | 重定向目标（如 0.0.0.0）—— `compose_rules_rule_redirect_hint`；相关：`compose_rules_redirect`（重定向）、`compose_rules_redirect_to`（→ %1$s） | 见设置页状态行（需截图确认最终措辞） | 输入框 | 重载后（hosts 档被拦域指向地址） |
| 允许清单（bypass blocking） | 放行名单（跳过拦截）—— `compose_settings_allowlist_title`；并带风险提示：名单内 UID 的流量不会被拦截，只用于门户登录等特殊情况、非必要不要添加（`compose_settings_allowlist_warning`） | 见设置页状态行（需截图确认最终措辞） | 开关 + 列表页 | 即时 |
| Web 服务器设置（端口/劫持） | 劫持未生效：本机 80/443（或你设置的端口）没有监听——可能被 AdGuard 等占用，或未授予 root。可在“网络服务器”里改用 8080/8443 后重试（劫持模式不依赖 80/443）。 | 见设置页状态行（需截图确认最终措辞） | 开关 + 端口输入 + 测试按钮 | 重载后/重启服务；失败时按文案提示改端口 |
| 轻量模式（省内存） | 占用最低：开机拉起服务器后，应用会在退到后台时退出进程（服务器作为独立原生进程继续运行，拦截不受影响），自愈检查从每 5 分钟降为每 6 小时一次。开启常驻通知时本项被忽略；劫持模式始终保留高频检查。 | 见设置页状态行（需截图确认最终措辞） | 开关 | 即时（下次请求生效） |
| 证书管理 / 一键信任 / 手动安装 / 固定证书应用 | 用户信任库（多数 App 默认不信任它 —— 系统级需写入 /system 或 APEX；其中 apexdata 非空时 Conscrypt 优先读它） | 见设置页状态行（需截图确认最终措辞） | 按钮 + 状态行（四态） | 即时（重新探测：安装·删除·重启后重算） |
