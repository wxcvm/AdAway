# 随服务器启动创建与严格 HTTPS 检查

IPv4、IPv6 独立输入，留空关闭对应协议。推荐 127.0.0.1 / ::1。缺失地址仍可通过“创建并应用”一次性操作；新增“随服务器启动创建缺失地址”可选项，需要应用后生效。默认关闭；旧版已有显式托管地址的安装保留原来的自动恢复行为。关闭选项不会删除正在使用的地址，但未来启动不再自动创建。

启用后，实际启动服务器前只在 lo 创建缺失的私有 IPv4 / ULA，本轮准备失败清理新增地址，已有地址不删除，清理失败保留记录并报告。启动及原生监听未就绪时清理本次启动创建的地址；操作不改变物理网卡、默认路由或 DNS。Linux 127/8 可本地绑定，不重复创建别名。

开机恢复还需启用已有 Root 开机脚本。脚本只恢复之前明确创建并记录、当前仍选用的托管地址；关闭随启动创建时更新脚本不再恢复这些地址。未知地址不根据订阅推断创建。实际 Android 17 / Root / SELinux / 重启验收不能从模拟器或宿主机测试推断。

AdGuard 检测增加 HTTPS：只连接当前本机监听，使用默认 SSLSocketFactory 的本应用信任策略，显式 HTTPS 名称校验和原域名 SNI/Host。只有严格证书验证与新鲜 nonce 加密回执均通过才显示 HTTPS 已到达；连接/TLS 未完成、证书拒绝、证书通过无回执分别报告。没有关闭 TLS 校验或自动安装 CA。本机基线使用 localhost SNI，域名路径只对匹配本机监听的 DNS 结果测试。单连接通过 watchdog 在 2.5 秒关闭，响应最多 4096 字节。

结果代表本应用所用信任策略；其他应用可忽略用户 CA、使用私有信任库或证书固定。当前 QUIC / HTTP/3 未实现，界面明确 TCP/443 与 HTTPS 通过不能证明 UDP/443 或 QUIC 已到达。没有更改 AdGuard、防火墙或网络以强制协议回退。

复用已有 libsu、平台 SSLSocket、NetworkInterface，无额外 TLS 库。JVM 和 API 30/35 夹具在内存中显式信任测试专用证书，验证双栈加密回执、未信任/错误名称拒绝、普通 HTTPS 页面不误认、非本机拒绝连接；测试私钥只位于 test/androidTest 资源，不进入生产 APK 或系统信任库。
